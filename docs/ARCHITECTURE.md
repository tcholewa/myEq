# Architecture

## Ownership and signal path

System clients → HAL mixed stereo output → `myEq.driver` WriteMix → shared-memory ring → app physical-output callback → Apple AUVarispeed clock correction → existing preamp/EQ/limiter → physical output.

The SwiftUI app owns presets and the editor. `AudioEngine` serializes session changes on its control queue. `VirtualOutputSession` opens only the physical output and disables every physical input stream before starting IO. The output callback is C++ and does not call Swift, allocate, lock, log, or perform IPC. There is no capture-tap fallback.

The output-only C++ AudioServerPlugIn publishes UID `com.tc.myEq.output`, one interleaved Float32 stereo stream, and hardware-proxy volume/mute controls. The host supplies the already mixed stream via WriteMix. Nominal rate changes follow the physical device using the host configuration-change handshake. The driver advertises no input and never calls the client HAL APIs from inside the driver. A host-time clock supplies zero timestamps at a 16,384-frame period.

The app includes the physical output name in the transport-open message; the bridge forwards this optional metadata with the driver attachment. The driver publishes `myEq: {physical output name}` only after HAL accepts the configuration, and notifies `kAudioObjectPropertyName` listeners when it changes. Detached sessions or absent names use `myEq`. Unicode names are preserved; the device UID, manufacturer, and stream name stay stable. Name storage uses the existing control-state mutex, with notifications outside the lock. No name processing, additional polling, or IPC is added to the audio callback. Device naming does not change the shared-memory layout. Protocol 3 additionally supports buffer preparation and explicit retirement notifications.

`myEqBridge` is a system LaunchDaemon running as `nobody`. Its global Mach service is listed in the driver's `AudioServerPlugIn_MachServices`, following [Apple QA1811](https://developer.apple.com/library/archive/qa/qa1811/_index.html). It brokers an anonymous `MAP_SHARED` mapping through XPC; samples never travel in messages or through the bridge's event loop. The installer records app/helper code hashes in a root-owned trust manifest. The driver carries the bridge hash in its own bundle, which is readable inside its sandbox. Incoming clients complete a two-message handshake: the first sets an XPC code-signing requirement, and the second must pass that requirement before a role or memory mapping is granted. Driver peers must be the Apple-signed audio-driver host; app and recovery peers must be the active console user in the same audit session. Only one app and recovery session are accepted.

## Transport and clocking

`Transport.hpp` defines protocol version 3: immutable format/size/generation fields, cache-line-separated atomic cursors and telemetry, lease state, and 16,384 stereo frames. A single driver WriteMix producer owns `written`; the app owns `read`. Acquire/release ordering protects ordinary sample storage. The writer drops incoming blocks when full and never overwrites unread samples or changes the reader cursor. Mapping headers, sizes, versions, rates, and generations are checked before use. Audio mappings remain alive until IO has stopped.

The physical callback starts after two blocks of the larger virtual/physical IO quantum are buffered (minimum 256 frames). The virtual output's [HAL buffer size](https://developer.apple.com/documentation/coreaudio/kaudiodevicepropertybufferframesize) is read during setup and on the existing control tick; bounded changes are handed to the renderer through a lock-free atomic. Increasing the quantum reprimes the renderer; decreasing it lets the drift controller settle to the smaller target. For a 512-frame source and 128-frame output, the target is 1024 frames (21.3 ms at 48 kHz), rather than 256 frames (5.3 ms); these are reserve targets, not measured end-to-end latency. A preallocated Apple AUVarispeed unit makes slow PI corrections around unity, bounded to ±0.2%, to compensate independent clocks at the same nominal rate. Discontinuities, overruns, and underruns discard buffered history, render silence, and reprime; a 5 ms input fade avoids abrupt restart. Non-finite source samples are contained. All buffers and the converter are prepared before IO; output callbacks larger than the supported storage are rejected and reported. Before renderer creation, generation-bound `prepareBuffers` asks recovery to request a 512-frame physical minimum, preserving larger values and respecting writability/range. It attempts to match the virtual HAL device, without inventing unsupported plug-in properties. Read-only/rejected requests keep the actual quantum. Accepted writes are read back, allowing up to 500 ms for visibility per device. Values outside 1–4096 fail safely. The app applies this policy once per explicit enable/output selection and absorbs its resulting physical-route snapshot, avoiding a self-induced rebuild. Automatic reconnection uses the then-current buffers; it does not re-enforce the floor after restoration or an external change. Session startup logs both actual buffer sizes, durations and target reserve; recovery logs original/requested/read-back values and HAL status; changed transport fault counters are logged from the control queue at most once every five seconds, without audio content or UI invalidation.

Core Audio owns the physical IOProc thread and its real-time scheduling. No Mach time-constraint override is installed. AUVarispeed is warmed with silent private buffers before IO starts; effective Float32 playback-rate changes alone trigger `AudioUnitSetParameter`. `AudioUnitReset` remains in the callback for re-priming and errors are checked. Both APIs need installed Audio System Trace / allocation profiling before claiming real-time safety of their opaque internals. Cursor/publication acquire-release ordering is unchanged; independent correction/source-running telemetry uses relaxed ordering. Meter CAS publication is bounded to four attempts and can drop a visual update under contention; fade length is precomputed.

`MYEQ_RENDER_TIMING=1` enables preallocated callback wall-time histogram counters at renderer creation. The control queue reports cumulative callbacks, maximum nanoseconds, counts exceeding half a period, and counts exceeding a full period every five seconds. Period uses actual callback frames/sample rate. Disabled builds/sessions do not collect timing data. These counters measure elapsed execution, including preemption, not scheduled wakeup lateness. Use Audio System Trace to distinguish CPU work, waits and scheduling delay; no timing diagnostic logs from the audio thread.

The driver applies no digital volume. The app proxies master volume/mute or paired channel controls to the physical device, retaining channel balance. Outputs without writable hardware controls remain fixed-volume. Controls are exchanged outside the audio callback.

## DSP contract

The C API in `CDSP.h` is shared by the audio engine, graph/model, and offline tests. `meq_prepare` and layout configuration require a stopped callback. A bounded single-producer/single-consumer queue transfers prepared coefficient banks from the control queue to the callback. If full, the latest desired preset remains pending and is retried by the next control tick. The callback drains to the newest bank when the previous 20 ms crossfade finishes. Filter coefficients are never interpolated through unstable intermediate values.

Eight double-precision biquads use Robert Bristow-Johnson's [Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/) equations, as published by W3C and edited by Raymond Toy. [Third-party notices](../THIRD_PARTY_NOTICES.md) record the source, adaptation details, and W3C license. Bell gain is ±24 dB with 0.05–5 octave bandwidth; shelf slope is 0.1–1; cut Q is 0.1–10, defaulting to Butterworth Q. Frequency is constrained to 20 Hz–min(20 kHz, 0.45 × sample rate). Stored frequencies survive output changes, while processing and graph positions use the effective frequency.

Auto preamp searches the combined response from DC through Nyquist, adds every band's center frequency to the search, and rounds attenuation upward to 0.1 dB. It can attenuate more than the manual control's −60 dB lower bound. The graph uses the same coefficient code and shows the linear response, including preamp; it does not depict the signal-dependent limiter.

The limiter has a 1 ms delay, linked left/right gain, a monotonic lookahead peak queue, a −0.5 dBFS sample ceiling, and 50 ms release. It is a sample-peak limiter, not an oversampled true-peak limiter. Its delay is in addition to Core Audio and hardware latency. All owned storage is allocated before audio starts; the owned DSP callback does not allocate, lock, log, perform file IO, or call Swift. This source-level claim does not prove that opaque Apple audio-unit internals never allocate or lock. Telemetry atomics are asserted lock-free at compile time. Null tap data means silence; changed buffer topology and non-finite samples increment fault counters.

## Stereo output metering

While the editor is visible, each callback accumulates separate left/right post-limiter sample peaks in one packed, lock-free 64-bit atomic. `meq_take_meter` atomically drains both channels together, retaining transients across all callbacks since the previous display poll. The shared gain-reduction reading also retains its maximum until consumed. `meq_meter` remains non-destructive so the health watchdog cannot steal a meter interval.

A separate 30 Hz control-queue timer in `OutputMeterMonitor` supplies `OutputLevels` to the main actor; the 250 ms HAL/health tick is unchanged. Meter polling is parked while capture is stopped or the editor is not visible. Bypass and suspension immediately reset display levels and peak markers. `OutputMeterEnvelope` provides immediate attack and elapsed-time-based 24 dB/second decay over −60 to 0 dBFS. Separate white peak markers hold each channel's peak for one second, then fall at 6 dB/second. New peaks refresh only their own channel's hold; an update crossing the hold deadline applies decay only to the remaining elapsed time. Numeric dBFS readings and accessibility values use the same held-peak values as the markers. At the meter floor, the markers disappear and the readouts show −∞ dBFS. This display smoothing does not affect audio.

`StereoOutputMeter` is a fixed-size `NSViewRepresentable` with no SwiftUI observation of the meter model. Its native view subscribes directly to envelope changes and updates persistent Core Animation layers with implicit animations disabled. Bar masks and markers change geometry; text layers update only when their displayed value changes. Live samples never invalidate intrinsic size or rebuild the SwiftUI meter hierarchy. The view handles display scale changes and exposes the peak values to accessibility. UI scheduling is best-effort, independent of the real-time audio deadline.

## Visibility and CPU use

An `NSViewRepresentable` separately observes the editor and menu panel’s actual `NSWindow` objects. It combines ordered visibility, miniaturization, application hiding, and [AppKit occlusion notifications](https://developer.apple.com/documentation/appkit/nswindow/didchangeocclusionstatenotification). A partly visible editor continues updating even when another app is active; a closed, minimized, hidden, or fully occluded editor stops visual work. Only editor visibility enables DSP metering. The menu panel refreshes a cached 128-point response preview when shown or when settings change; it never enables the meter timer. The [menu design specification](MENU-DESIGN.md) documents layout and interaction behavior.

Visual DSP metering defaults off. `meq_set_metering_enabled` changes an atomic epoch once per visibility transition. At the next block boundary, the audio thread chooses a compiled render path that omits output-peak accumulation, minimum-gain tracking, dB conversion, and meter publication when hidden. EQ, limiter processing, callback counters, and fault detection run in both paths. Epochs discard prior readings even if a complete hide/show cycle occurs between callbacks; an old in-flight callback cannot publish a peak accepted by the new interval.

`OutputMeterMonitor` parks its timer and invalidates queued main-thread deliveries on hide or session changes. Its delivery-validation lock is used only by the control and main queues, never the real-time callback. The app also rejects meter updates while hidden, cancels pending graph work, skips graph drawing, and recalculates the response from current settings when shown. Engine snapshots are published only when user-facing status changes; callback/fault counters remain internal to the watchdog, eliminating unchanged 4 Hz editor/menu invalidations.

## Editor and menu presentation

The 0.3.0 interface uses a shared `Studio` palette, native SwiftUI layout, Canvas response/filter shapes, and the existing fixed-size AppKit meter. `EqualizerView` adapts graph height, fader height, and spacing below 820 points of content height, while preserving exact-value fields and all eight strips. Error messages remain in a scrollable content region; output, power, and the level footer remain fixed. No decorative animation or recurring UI timer is added.

`MenuBarExtra` uses a window presentation with output selection, preset controls, a cached 128-point combined response, and an editor shortcut. `AppModel` tracks menu/editor visibility independently. Opening the panel refreshes only its curve if the editor is hidden; changes while both are hidden cancel pending graph work. Opening either surface refreshes it from current settings. Native menus are created on demand through `PopupMenuButton`: a regular SwiftUI button provides the custom label and keyboard/accessibility behavior, and an anchored `NSMenu` provides selection, checkmarks, and disabled actions. Menu item instances retain their action closures for the menu’s lifetime.

Band selection is optional and initially empty. A window-scoped local mouse-down observer uses geometry preferences for the visible scroll viewport, eight band strips, and graph. It selects a clicked band without consuming the mouse event, and clears selection/field editing for clicks elsewhere; graph node hit testing owns graph selection. The viewport check prevents a scrolled, clipped strip from intercepting header/footer clicks. The observer removes its monitor on detachment and has no polling timer.

A separate source-rendering utility constructs `AppModel(preview: true)`, preventing preference reads/writes, helper registration, and audio activation. Never-shown windows host fixture views for bitmap rendering. This verifies layout and visibility/model behavior without controlling the installed app; real menu interaction and window lifecycle still need a live check.

The band-selection observer also provides a neutral native initial responder, so AppKit does not automatically highlight the first numeric field. Initial attachment and reopening after close clear both focus and band selection once, after SwiftUI finishes attaching its controls. Returning to an already open editor preserves deliberate editing focus. Mouse-down cancels any pending initial reset, and Tab still enters the normal key-view loop. An unchanged numeric binding write does not select a band or save settings.

## Lifecycle and recovery

`myEqRecovery` is an independent per-user LaunchAgent registered by `SMAppService`. It is the sole owner of default-route writes. Before buffer mutation it writes a schema-3 recovery journal containing routes plus at most two device UID/original/applied buffer entries; schemas 1 and 2 remain readable. Buffer restoration requires the same UID and current value equal to myEq’s applied value, so an external change is preserved. Missing devices are skipped; failed restoration remains pending. Before activating it persists the journal, asks the bridge to activate the prepared renderer's lease, waits for driver availability, then redirects both default media and system sounds. The original alerts destination is preserved separately. Bypass/quit restores the current physical destination before the app stops its renderer. Cleanup changes a default only if it still points at myEq.

The app and recovery agent send health checks every 250 ms. The bridge revokes immediately for peer death or ownership loss. App heartbeat and render progress have 1.5-second limits; recovery heartbeat has a two-second limit. The bridge samples render progress on its own timer and caps the shared lease at the earliest of those deadlines. Late heartbeats cannot revive an already expired session. The driver independently enforces that deadline. A missing 500 ms bridge or recovery-status reply is tolerated only while the matching generation’s shared-memory lease remains active and unexpired, with no recorded connection failure. The client never extends this deadline. Explicit errors, invalid replies and confirmed peer failures still fail immediately. Recovery tolerates isolated bridge RPC timeouts for up to two seconds since its last successful reply, without extending grace on retries. Active-session HAL device/route queries run on a separate serial worker; generation/epoch checks discard stale results on the state queue. Startup and restoration HAL work remains serialized on the lifecycle queue while no session is playing. If its journal survives a crash, it retries restoration when it next runs. No samples are journaled.

A manual media-default change bypasses and updates the app's enable preference. A destination disconnect instead allows fallback: preserve a physical destination already selected by macOS, otherwise select available built-in output, then another available physical output. This fallback is not restricted to EQ-compatible formats; ordinary playback is restored first, and EQ resumes only on a supported stereo route. The previous disconnected destination is not automatically reclaimed. Bluetooth hands-free mode remains suspended until stereo returns.

Screen lock does not itself suspend audio. The app checks the documented Window Server session UID, on-console and completed-login properties on its existing control tick. Session-switch notifications prompt that check rather than setting the system-sleep flag. Missing or ineligible session state suspends before heartbeat processing; the bridge and recovery helper retain independent console UID, audit-session, signature and generation checks. The app holds a user-initiated activity allowing idle system sleep from audio startup through teardown; recovery holds one from activation through restoration settlement, releasing it on ownership loss, sleep or bridge failure. No new display/system-sleep prevention assertion or visual polling is added. These changes address potential lock-related scheduling and recovery failures; the user reported a successful manual-lock check on 0.4.4, while automatic screensaver and sustained locked playback checks remain pending.

Accepted XPC connections explicitly target the owning serial queue. `serialEvents` hands event work onto that queue, and asynchronous reply completions use the same explicit handoff. Listener configuration alone does not serialize its accepted peers: the XPC default target is a separate queue. This makes peer ownership, session generation, retirement, deadlines and recovery transitions share one ordering domain; the native control fixtures run under ThreadSanitizer in CI.

Bridge and recovery services use launchd `ProcessType=Interactive`, because their short control deadlines directly sustain user-requested audio. The bridge's serial queue explicitly uses user-initiated QoS; recovery already used that queue QoS. These remain unprivileged control services with no Mach real-time scheduling override. Maintenance accepts exactly the legacy Background schema and the current Interactive schema for upgrades/rollback, with all other launch configuration fields fixed.

`ConsoleUserMonitor` subscribes to the [console-user dynamic-store key](https://developer.apple.com/documentation/systemconfiguration/scdynamicstorekeycreateconsoleuser(_:)) using a separate notification queue. Heartbeat ownership checks read one atomic UID/revision snapshot instead of synchronously calling configd. A notification invalidates the snapshot before an asynchronous refresh; missing identity or configd restart fails closed. Compare/exchange publication rejects a query whose revision has been superseded. Initial subscription and initial read occur before admitting sessions. On a change, authorization resumes only after the new value is published; real lock/user-switch notification behavior remains a live acceptance test. This does not cache permission across a known ownership change.

After route activation, an independent user-initiated serial queue renews the app heartbeat every 250 ms (25 ms leeway). It performs only bounded helper RPCs, with no HAL discovery, volume queries or UI work. The engine reads a synchronized cached health result; unhealthy results latch and stop the heartbeat timer until teardown/reconnection. Teardown cancels and drains this queue before restoring routes or destroying the connection, preventing callbacks from using a retired pointer. The health-result lock is never used by audio IO. This isolates lease renewal from slow device queries on the main audio-control queue; it does not guarantee timely audio callbacks under CPU saturation. The bridge still requires both authenticated peers and advancing render callbacks within the deadlines above. Engine transition/error and transport-counter diagnostics use structured public logging for diagnostic values, without audio or device names.

Rate, buffer size, device topology, sleep/wake, and audio-service changes rebuild the session. Driver/helper failures leave ordinary playback restored. Startup failures carry an optional `retryable` reply flag through the control protocol; timeouts, interrupted/unavailable XPC connections, pending driver/helper readiness, and aborted HAL configuration can be retried. Explicit protocol/signature/configuration failures remain terminal. The engine uses its existing 250 ms control tick for four retries after delays of 0.25, 0.5, 1, and 2 seconds, without sleeping on the main thread or adding a timer. Transient running-session failures use the same four-attempt budget and show Reconnecting. Bypass, output changes, explicit Retry, sleep/wake and console-eligibility transitions reset the budget; otherwise only 30 continuous seconds of healthy playback reset it. A brief successful reconnect does not reset the budget. Permanent authentication/protocol failures and exhausted retries expose Retry. Heartbeat retryability crosses the native/Swift boundary explicitly, using existing typed XPC retryability metadata; it is never inferred from error text. The bridge permits a retryable expired-heartbeat response only for the current paired owner and exact retired generation, with no active replacement session.

Helper registration completion configures and retries the engine in one queued operation. While registration is pending, edits do not enqueue an enabled session with a false readiness flag; an explicit disable still takes effect. Session revocation sends `detach` only when it actually removes a transport, so recovery restore, app close, and subsequent disconnect events do not repeatedly enqueue HAL reconfigurations. Visual metering remains gated independently of audio health monitoring.

## Persistence, installation, and validation

Settings schema 2 adds an optional preferred output UID. Version-1 presets and enable preference migrate in memory; the next atomic save writes version 2. Invalid or unknown schemas retain the existing preserve-before-reset behavior.

The personal package installs `/Applications/myEq.app`, `/Library/Audio/Plug-Ins/HAL/myEq.driver`, the global bridge, its launchd plist, and the trust manifest. The recovery executable and LaunchAgent plist are embedded in the app. Package components are not relocatable, so Installer cannot upgrade a development copy by mistake. App/driver/helper signatures are verified during packaging and installation. Installing requires administrator authorization and targets the current startup disk. The installer welcome screen discloses a brief system-wide audio interruption. After signature verification, maintenance compares the current driver/bridge identities with the fully validated protected upgrade snapshot. Fresh installs and changed identities require a Core Audio reload after bridge bootstrap; identical driver/bridge identities keep the daemon running. An unsafe snapshot or malformed policy fails installation instead of authorizing a skipped reload. This preserves the daemon, but does not guarantee a restart-free upgrade: the tested 0.4.3 installation unloaded the unchanged driver during bundle replacement and required a manual reload to restore the virtual output. A future restart-free update path must preserve the driver files as well as the daemon. Building a package does not reload audio. Manual recovery, rollback, and uninstall can use `sudo killall -TERM coreaudiod`; a full Mac restart is an alternative. Upgrade/removal invokes a verified, privately staged snapshot of the previous recovery helper as the console user before unloading services. A previous package is retained for rollback, and uninstall preserves user presets.

Postinstall adds a fresh installation UUID to the root-owned trust manifest, including on same-build reinstalls. The app remembers the last successfully registered UUID per user. If an approved helper still has an old registration, the app awaits ServiceManagement unregistration before registering it for the new installation. This repairs the stale `enabled` status left after installer `bootout`, without refreshing the helper on every ordinary launch. Registration runs before audio is enabled, concurrent retries are coalesced, and a user-disabled helper remains subject to Background Items approval.

Packaging also writes an explicit `SpawnConstraint` into the embedded recovery LaunchAgent plist before signing the app. It requires the recovery signing identifier and this build's exact binary code-directory hash. This follows Apple's [launchd constraint mechanism](https://developer.apple.com/videos/play/wwdc2023/10266/) and [binary `cdhash` format](https://developer.apple.com/documentation/security/defining-launch-environment-and-library-constraints). It avoids relying on an inferred ad-hoc requirement retained by Background Task Management across helper updates. `scripts/verify-installer.py` expands the package and checks that the launch constraint, XPC trust manifest, and embedded helper all identify the same signed binary.

Build products and temporary packaging files live under `build/artifacts.noindex`; temporary packaging trees are removed on exit. Installer rollback copies also use `.noindex` directories. This keeps generated apps and retained backups out of Spotlight while preserving `/Applications/myEq.app` as the launchable installation.

This is locally ad-hoc signed, not notarized distribution. The architecture uses no recording-input or process-tap API; the expected absence of capture indicators must be verified on the target macOS release. The initial tests cover offline rendering and mocked recovery, not installed-system crash recovery, real-device performance, or end-to-end latency. See VERIFICATION.md for the current acceptance status.

## Security protocol (0.4)

All state-changing control requests carry the bridge-generated session generation. The bridge checks the current connection, active console UID, paired audit session, and generation before acting. Recovery accepts only its own user's audit session. Replacing or losing a peer invalidates pending work. Two-message code-signing authentication remains mandatory; incomplete handshakes expire after two seconds (checked before each message as well as by timer), with at most 32 pending peers. Requests requiring responses must carry reply context; typed, bounded schemas reject ambiguous success and unsupported fields. Output names and UIDs are limited to 1,024 UTF-8 bytes; operation/role names to 32 bytes; error text to 2,048 bytes.

Bridge and recovery peer requests use asynchronous deadlines on serial control queues. Every revoked generation remains retired until recovery restores routes/buffers and acknowledges settlement. The bridge sends a generation-tagged `retired` notification, including when setup fails before activation, so an idle recovery helper can settle that transaction. The bridge accepts no new open during that interval. This orders route restoration before a new activation. Configuration revisions prevent a late HAL configuration callback from attaching an obsolete mapping. The driver checks the lease deadline in every WriteMix callback, independent of the control timer; shared-memory bounds remain compile-time constants and validated metadata is cached locally.

Settings reads are bounded to 4 MiB, trust manifests to 64 KiB, and recovery journals to 16 KiB. Descriptor-based reads reject symlinks, nonregular files, extra hard links, unexpected ownership, writable modes, and ACLs. Settings/journals use exclusive temporary files and atomic replacement in a user-owned directory; files are 0600 and the directory 0700. Recovery journal schema 2 records UID, audit session and generation; legacy schema 1 supplies routing hints only and never grants session authority. The bridge remains unprivileged and no filesystem work is added to audio callbacks.

## Maintenance and distribution security

The one-shot `myEqMaintenance` executable runs only during administrator-authorized installation, rollback or removal; it is not a persistent privileged service. Its operations and target paths are fixed. It walks directory descriptors without following links, checks ownership/modes/ACLs and validates component signatures against the root-owned manifest. Standard root-owned `/Applications` permissions are supported. It rejects unsafe trees instead of recursively repairing ownership. A verified snapshot supplies the recovery executable; rollback uses staged atomic swaps, while removal quarantines exact targets and checks inode identity before deleting them. Recovery snapshots are retained on failure and after uninstall. Apple Installer still performs the package payload deployment; clean-Mac and concurrent-substitution testing remains a release requirement.

The manifest binds app, bridge, recovery, driver and maintenance code hashes. Runtime root-owned manifest reads also validate every ancestor directory and reject symlinks. Postflight validates the complete installation before writing its new UUID and starting services. The embedded driver's bridge trust read is bounded to 64 KiB. Trust material and signing constraints are generated after component signing; production builds verify the expected Developer ID Team, timestamps and hardened runtime. Signing credentials stay out of ordinary CI. See [releasing](RELEASING.md) for the separate signed-candidate workflow and manual hardware gate.
